# D:\SRTP 项目长期记忆

## 项目是什么
SRTP 本科生科研训练项目：**《基于特征解耦与知识增强的"电力看经济"智能体构建方法》**
核心命题：电力数据高频客观，是经济先行指标；但电量波动混杂天气/节假日/电价/新能源/政策等非经济因素。
要做的事：**把经济信号从非经济扰动中剥离出来，并解释它、报告它、回答关于它的问题。**

## 五步主线（贯穿全项目的技术骨架）
多源数据输入 → 特征解耦 → 知识增强诊断（VAE + KG + RAG）→ 多智能体协同 → 智能输出
对应开题四个研究目标：感知 / 诊断 / 生成 / 协同

## 产品终局定位（2026-09-14 用户明确）
**做电力经济领域的 "Claude Code"**：接入大模型 API，用户输入一个地区的电力数据，
系统自主判断该地区的经济状态并给出可核查的解释。

这个定位带来的关键判断标准（后续所有工作都要对着它检查）：
- **LLM 必须在驾驶座**：由模型自己决定调哪些工具、调几次、何时停止。
  现有的 power_econ_agent 是"固定流水线 + 结尾挂个 LLM"，不满足这一点，需要改造。
- **数据接入必须通用**：要能接任意地区、任意频率的电力数据，不能写死 schema 和路径。
- **输出必须可核查**：结论 / 证据 / 反证 / 置信度 / 不确定性，五段式。
- **工具描述质量决定成败**：LLM 靠 tool docstring 理解工具用途，描述写不好模型就不会用。
- **必须有评测集**：没有客观评分就无法判断"判断得准不准"。

## 必须遵守的项目原则
1. **相关性 ≠ 因果**。KG 中只能用 `MAY_AFFECT` / `CANDIDATE_CAUSE`，禁止写 `causedBy`。输出的是"带证据和不确定性的原因候选"。
2. **只使用历史信息**做分解与预测，严禁数据泄漏（时间硬切分，绝不 shuffle）。
3. 数据构造风险必须显式标注：Q4 由累计差分 → `revision_risk`；STL 首尾周期 → `endpoint_warning`。
4. 天气为代理变量时必须声明（如江苏用南京单点 ERA5 代全省）。
5. 对外交付要诚实标注"合成数据"与"真实数据"的区别，不夸大精度。
