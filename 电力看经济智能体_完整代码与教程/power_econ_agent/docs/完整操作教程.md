# 第二部分：特征解耦

## 11. 为什么要“过去信息限定”

若用完整时间段的均值、周期模板或未来发布的宏观数据构造训练特征，测试集会泄漏未来信息，得到虚高结果。因此本项目规定：时间 `t` 的预测输入最多只能使用 `t-1` 及更早的数据。

## 12. 因果多尺度分解

代码：

```text
src/power_econ/features/decomposition.py
```

负荷被表示为：

\[
L_t = T_t + D_t + W_t + R_t
\]

其中：

- \(T_t\)：只使用过去负荷的指数移动趋势；
- \(D_t\)：同小时历史残差的过去均值；
- \(W_t\)：同“星期×小时”历史残差的过去均值；
- \(R_t\)：无法被上述项解释的不规则残差。

实现中的 `past_group_mean` 明确排除当前行，避免把被预测时点本身写入周期模板。

## 13. 五个特征组

### 13.1 负荷组

包括：

- 原始负荷；
- 趋势、日周期、周周期、残差；
- 一阶差分；
- 24/168 小时滚动均值和标准差；
- 残差滚动均值；
- 负荷率。

### 13.2 天气组

包括：

- 温度、湿度、降水、风速；
- 制冷度时 `cdd=max(T-24,0)`；
- 采暖度时 `hdd=max(10-T,0)`；
- 相对历史气候模板的温度异常；
- 温湿综合压力。

### 13.3 日历组

包括：

- 小时、星期、月份的正余弦编码；
- 周末；
- 节假日；
- 生产经营时段。

### 13.4 宏观组

包括六个“已发布值”特征：

```text
industrial_yoy_published
pmi_published
retail_yoy_published
power_consumption_yoy_published
electricity_price_index_published
renewable_share_published
```

若 `release_lag_months=1`，当月预测只能看到上月宏观数据，原始当月值保留为 nowcast 目标，不作为提前已知输入。

### 13.5 事件/数据质量组

包括：

- `policy_event`；
- `sensor_quality`；
- `missing_fraction`。

这样 VAE 和诊断规则可以把传感器异常与真实物理负荷异常分开。

# 第三部分：模型训练

## 15. 时间顺序切分

默认：

```yaml
train_ratio: 0.70
val_ratio: 0.15
```

即：

- 前 70%：训练；
- 中间 15%：验证、早停和异常阈值校准；
- 最后 15%：最终测试。

不做随机打乱式时间切分。

## 16. 季节基线 + 残差学习

对每个目标时点，先构造周季节朴素基线：

\[
B_{t+h}=L_{t+h-168}
\]

若历史不足，退化为 24 小时滞后，再退化为最近可用值。

模型学习的是：

\[
y_{t+h}=L_{t+h}-B_{t+h}
\]

最终预测：

\[
\hat L_{t+h}=B_{t+h}+\hat y_{t+h}
\]

这样可把稳定周周期交给透明基线，让神经网络集中学习天气、事件和经济等偏移。

## 17. 特征解耦预测网络

代码：

```text
src/power_econ/models/forecaster.py
```

### 17.1 每组独立编码

每个特征组在回看窗口中提取八类统计：

1. 最后时点；
2. 最近 24 小时均值；
3. 最近 24 小时标准差；
4. 整个窗口均值；
5. 整个窗口标准差；
6. 首尾变化；
7. 最大值；
8. 最小值。

这些统计进入独立 MLP 编码器，形成组上下文：

\[
h_g=Encoder_g(X_g)
\]

### 17.2 动态门控融合

每组得到一个时变权重：

\[
\alpha_g=softmax(Gate(h_g))
\]

融合上下文：

\[
h=\sum_g \alpha_g h_g
\]

门控权重会随输入变化，可观察当前预测更依赖负荷、天气、日历、宏观还是事件。

### 17.3 多步分位数输出

每个未来步长加入独立 horizon embedding，输出：

- P10：下界；
- P50：中位数；
- P90：上界。

通过 `softplus` 约束 P10 ≤ P50 ≤ P90，避免分位数交叉。

### 17.4 损失函数

总损失：

\[
\mathcal L=\mathcal L_{quantile}+\lambda\mathcal L_{orthogonality}
\]

- `quantile_loss`：三分位 pinball loss；
- `orthogonality_loss`：惩罚不同组上下文过度相似，鼓励解耦；
- `disentangle_weight`：控制解耦惩罚强度。

## 18. 序列 VAE 异常模型

代码：

```text
src/power_econ/models/vae.py
```

输入选择：

- 负荷残差；
- 负荷差分；
- 24 小时波动；
- 温度及温度异常；
- 湿度；
- 政策事件；
- 传感器质量；
- 缺失比例。

GRU 编码器输出潜变量分布 \(\mu,\log\sigma^2\)，解码器重构输入序列。损失：

\[
\mathcal L_{VAE}=MSE(X,\hat X)+\beta KL(q(z|X)||p(z))
\]

推理时使用潜变量均值解码，重构误差越大，表示当前多变量模式越偏离常态。

## 19. 异常分数融合

### 19.1 预测偏差分数

\[
s_f=\frac{|L_t-\hat L_t^{P50}|}{max((P90-P10)/2,\epsilon)}
\]

### 19.2 VAE 重构分数

\[
s_v=MSE(X_{t-k:t},\hat X_{t-k:t})
\]

### 19.3 稳健归一化

验证集上计算中位数和 MAD：

\[
z=max\left(\frac{s-median(s)}{1.4826\cdot MAD(s)},0\right)
\]

### 19.4 融合

\[
s=0.65z_f+0.35z_v
\]

阈值为验证集融合分数的指定分位数，演示默认 97.5%，真实配置默认 99%。测试标签不参与阈值选择。

## 20. 经济指标 nowcast

代码：

```text
src/power_econ/models/nowcast.py
```

先按月聚合：

- 月电量、均值、峰值、谷值、标准差；
- 负荷率、峰谷比；
- 残差均值、绝对均值、波动；
- 生产时段/夜间负荷；
- 温度、天气压力；
- 节假日占比；
- 数据质量。

然后使用标准化 + Ridge 对 `industrial_yoy`、`pmi` 或 `retail_yoy` 做时间后移测试。

## 24. 特征组消融解释

对某事件索引，先计算完整输入预测，再依次把某组标准化特征置零，即替换为训练均值：

\[
Contribution_g=\hat y(X)-\hat y(X_{-g})
\]

绝对贡献归一化后得到组重要度。该方法不是严格 Shapley 值，但计算快、组语义明确，适合在线原型。

## 25. 知识图谱和规则

规则文件：

```text
knowledge/domain_knowledge.yaml
```

每条原因规则包含：

- 原因 ID 和中文名称；
- 类别：weather/calendar/policy/data/economic 等；
- 基础权重；
- 触发条件；
- 证据模板；
- 反证条件；
- 图谱关联节点。

典型原因：

- 极端高温/低温；
- 节假日效应；
- 需求响应/错峰；
- 传感器或数据质量问题；
- 工业活动走弱/走强；
- 新能源净负荷扰动。

规则引擎根据事件残差、天气、日历、质量、门控和宏观背景计算候选分数。

## 26. 本地 RAG

知识文档位于：

```text
knowledge/docs/
```

当前使用字符 n-gram TF-IDF，优点：

- 完全离线；
- 无外部向量数据库；
- 中文短文本稳定；
- 结果可追溯到文档和章节。

诊断查询由事件方向、首要候选原因和“电力看经济”问题组合，返回相关知识片段。

## 27. 诊断智能体

代码：

```text
src/power_econ/agents/diagnosis.py
```

输入：异常事件。

处理顺序：

1. 定位事件在特征表中的索引；
2. 特征组消融；
3. 规则/知识图谱原因排序；
4. 本地知识检索；
5. 交给模板提供器或 OpenAI 结构化生成；
6. 写入 SQLite。

命令：

```bash
power-econ diagnose 6786696aebfd6c7c -c configs/demo.yaml
```

输出明确区分：

- 原因候选；
- 证据；
- 反证；
- 经济信号；
- 不确定性；
- 是否需要人工复核。

## 28. 为什么不能把一次负荷下降直接写成经济走弱

系统首先检查：

1. 数据质量是否正常；
2. 是否有极端天气；
3. 是否在节假日/调休；
4. 是否有需求响应、限电、错峰或检修；
5. 下降是否集中在生产时段；
6. 是否连续多日而非单点；
7. 宏观/行业指标方向是否一致。

只有非经济扰动解释不足、持续性和时段特征成立、多源证据一致时，才输出“与经济活动方向一致，需要复核”，不会输出“已证明经济衰退”。

# 第七部分：真实项目落地流程

## 37. 阶段一：数据审计

至少确认：

- 负荷口径是总负荷、售电量还是净负荷；
- 时间分辨率和时区；
- 是否包含光伏/风电反送；
- 是否有计量替换、补抄和口径变更；
- 能否获得行业、园区或电压等级分项；
- 能否获得需求响应、检修、限电、重大活动日志；
- 宏观指标的发布日期，而不是统计所属月份。

## 38. 阶段二：先跑 CSV 全本地模式

把四类数据放入：

```text
data/input/load.csv
data/input/weather.csv
data/input/macro.csv
data/input/events.csv
```

复制配置：

```bash
cp configs/csv_data.yaml configs/my_region.yaml
```

修改路径、区域和模型参数，然后：

```bash
power-econ collect -c configs/my_region.yaml --refresh
power-econ features -c configs/my_region.yaml
power-econ train -c configs/my_region.yaml
```

## 39. 阶段三：历史回放验收

建议选择至少 12–24 个月历史，并整理一个人工标注表：

```csv
timestamp,cause,severity,confirmed,notes
2024-07-15 14:00:00,extreme_heat,high,1,高温红色预警
2024-09-06 10:00:00,demand_response,medium,1,调度通知编号...
```

验收至少包括：

- 预测 MAE/RMSE/MAPE；
- P10–P90 覆盖率；
- 异常 Precision/Recall/F1/AP；
- 按原因分类召回；
- 误报原因统计；
- 诊断 Top-1/Top-3 命中率；
- 报告结论人工一致率；
- 运行时延。

## 40. 阶段四：规则和知识本地化

修改：

```text
knowledge/domain_knowledge.yaml
knowledge/docs/*.md
```

建议补充：

- 当地峰谷电价规则；
- 行业生产规律；
- 重大企业检修；
- 需求响应流程；
- 新能源装机和消纳特点；
- 当地节假日/旅游/会展影响；
- 统计口径说明。

## 41. 阶段五：滚动更新

推荐：

- 每小时/每日追加负荷与天气；
- 每月更新宏观指标；
- 每月或每季度滚动重训；
- 验证集随时间前移；
- 监控误差、区间覆盖率、异常率、特征分布和门控权重漂移；
- 模型升级保留版本号和可回滚产物。

## 42. 增加新的数据源

实现一个返回 DataFrame 的客户端，并在 `data/pipeline.py` 中合并。时间列统一为 `timestamp`，宏观月度列统一为 `month`。

## 43. 增加行业分项特征组

在 `FeatureBuilder.transform` 中添加：

```python
groups["industry"] = [
    "industrial_load_mw",
    "commercial_load_mw",
    "residential_load_mw",
]
```

模型根据 `feature_spec.json` 自动建立新分支和门控，不需要改预测网络主体。

## 44. 增加新的原因规则

在 `knowledge/domain_knowledge.yaml` 添加原因节点和规则。建议同时在 `knowledge/docs` 添加解释文档，使规则证据和 RAG 文本一致。

## 45. 替换预测模型

只要新模型提供：

```python
{
    "quantiles": Tensor[B, horizon, 3],
    "gate_weights": Tensor[B, groups],
    "contexts": Tensor[B, groups, hidden]
}
```

就可以复用训练、推理、异常融合和智能体层。

## 47. 常见错误

### `缺少特征文件`

执行：

```bash
power-econ features -c 你的配置.yaml
```

### `缺少模型文件`

执行：

```bash
power-econ train -c 你的配置.yaml
```

### `负荷 CSV 不存在`

核对配置相对路径。相对路径以项目根目录为基准。

### Open-Meteo 请求失败

- 检查联网；
- 增大 `timeout_seconds`；
- 或改为 `weather.provider=csv`。

### AKShare 某个指标失败

系统会保留其他成功指标并记录警告。若所有接口失败，改用本地宏观 CSV。

### 内存不足

降低：

```yaml
forecaster:
  batch_size: 64
  hidden_dim: 24
vae:
  batch_size: 64
```

### 训练过慢

- 缩短 `lookback`；
- 减少 `epochs`；
- 先用 `configs/quick_test.yaml` 验证；
- 检查是否正确安装带 CUDA 的 PyTorch。

### 报告没有异常

这不一定是错误。检查时间段是否覆盖异常，或执行：

```bash
power-econ scan -c configs/demo.yaml --limit 30
```

从结果中选择有事件的日期范围。
