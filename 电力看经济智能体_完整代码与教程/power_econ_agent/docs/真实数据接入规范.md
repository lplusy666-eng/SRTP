# 真实数据接入规范

## 1. 总则

所有 CSV 使用 UTF-8 编码，首行是字段名。时间序列建议连续、升序、无重复。相对路径以项目根目录为基准。

生产环境应保留原始文件，不要直接覆盖；本项目的统一结果写入配置指定的 `raw_dir`。

---

## 2. 负荷数据 `load.csv`

### 2.1 必需字段

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `timestamp` | datetime | — | 时点；无时区时按配置时区解释 |
| `load_mw` | float | MW | 总负荷或明确口径的功率 |

示例：

```csv
timestamp,load_mw
2024-01-01 00:00:00,1280.5
2024-01-01 01:00:00,1241.2
```

### 2.2 推荐字段

| 字段 | 类型 | 范围/单位 | 说明 |
|---|---|---|---|
| `region` | string | — | 区域/供电单位 |
| `sensor_quality` | float | 0–1 | 计量质量，1 为正常 |
| `industrial_load_mw` | float | MW | 工业分项 |
| `commercial_load_mw` | float | MW | 商业分项 |
| `residential_load_mw` | float | MW | 居民分项 |
| `solar_generation_mw` | float | MW | 分布式/集中式光伏 |
| `wind_generation_mw` | float | MW | 风电 |
| `net_import_mw` | float | MW | 区外受入，口径需说明 |
| `electricity_price` | float | 元/MWh 或元/kWh | 必须统一单位 |

当前默认特征会直接使用 `sensor_quality`。其他字段可在 `FeatureBuilder` 中添加为新特征。

### 2.3 数据要求

- 建议至少 12 个月，最好 24–36 个月；
- 小时级至少约 8,760 行/年；
- 长缺口必须保留质量标记；
- 负荷必须非负，若存在反送电，应另设净负荷字段并明确口径；
- 若计量口径变化，提供事件记录；
- 夏令时地区需明确时区，本项目中国场景默认 `Asia/Shanghai`。

## 3. 气象数据 `weather.csv`

| 字段 | 类型 | 单位 | 必需 |
|---|---|---|---|
| `timestamp` | datetime | — | 是 |
| `temperature_2m` | float | °C | 是 |
| `relative_humidity_2m` | float | % | 推荐 |
| `precipitation` | float | mm | 推荐 |
| `wind_speed_10m` | float | km/h 或统一后的 m/s | 推荐 |

示例：

```csv
timestamp,temperature_2m,relative_humidity_2m,precipitation,wind_speed_10m
2024-01-01 00:00:00,7.2,73,0.0,8.4
2024-01-01 01:00:00,6.8,75,0.0,7.9
```

配置：

```yaml
data:
  weather:
    provider: csv
    csv_path: data/input/weather.csv
```

注意：默认 Open-Meteo 风速字段单位由其 API 参数决定。若自行提供 CSV，整个文件必须使用同一单位，并在项目文档中记录。

## 4. 宏观数据 `macro.csv`

### 4.1 字段

| 字段 | 类型 | 单位/含义 | 必需 |
|---|---|---|---|
| `month` | date | 月份，建议当月 1 日 | 是 |
| `industrial_yoy` | float | 工业增加值同比，% | 推荐 |
| `pmi` | float | PMI 指数 | 推荐 |
| `retail_yoy` | float | 社零同比，% | 推荐 |
| `power_consumption_yoy` | float | 全社会用电同比，% | 推荐 |
| `electricity_price_index` | float | 电价/投入成本代理 | 推荐 |
| `renewable_share` | float | 0–1 | 推荐 |

示例：

```csv
month,industrial_yoy,pmi,retail_yoy,power_consumption_yoy,electricity_price_index,renewable_share
2024-01-01,6.8,49.2,5.5,11.8,-2.5,0.231
2024-02-01,7.0,49.1,5.5,11.0,-2.7,0.235
```

### 4.2 发布时滞

配置：

```yaml
macro:
  provider: csv
  csv_path: data/input/macro.csv
  release_lag_months: 1
```

`release_lag_months=1` 表示模型预测某月时只能使用上月宏观值。若掌握精确发布日期，建议进一步把月度特征改为基于 `release_date` 的 as-of join，而不是固定月数。

### 4.3 缺失处理

- 月度值向后填充到小时；
- 只允许过去值向后延续，不用未来值回填历史；
- 最早若无值，使用中性默认值仅用于维持管线；真实研究应增加“数据不可得”标记。

## 5. 事件数据 `events.csv`

| 字段 | 类型 | 说明 | 必需 |
|---|---|---|---|
| `date` | date | 事件日期 | 是 |
| `policy_event` | int | 需求响应、限电、错峰等，0/1 | 推荐 |
| `event_name` | string | 事件名称/通知编号 | 推荐 |
| `is_holiday` | int | 覆盖节假日，0/1 | 可选 |
| `is_workday_override` | int | 调休工作日，1 表示工作日 | 可选 |

示例：

```csv
date,policy_event,event_name,is_holiday,is_workday_override
2024-05-04,1,需求响应演练,1,0
2024-05-06,1,错峰生产通知,0,0
2024-02-18,0,春节调休工作日,0,1
```

当前为日级事件。若需要小时级起止时间，可扩展为：

```csv
start_time,end_time,event_type,event_name,affected_mw,source_id
2024-07-15 13:00:00,2024-07-15 16:00:00,demand_response,迎峰度夏需求响应,120,DR-2024-0715
```

并在 `calendar.py` 中按时间区间匹配。

## 6. 全本地 CSV 配置

复制：

```bash
cp configs/csv_data.yaml configs/my_region.yaml
```

关键配置：

```yaml
project:
  region: 实际区域
  timezone: Asia/Shanghai
  latitude: 30.2741
  longitude: 120.1551

data:
  mode: csv
  frequency: 1h
  load_csv_path: data/input/load.csv
  event_csv_path: data/input/events.csv
  weather:
    provider: csv
    csv_path: data/input/weather.csv
  macro:
    provider: csv
    csv_path: data/input/macro.csv
    release_lag_months: 1
```

运行：

```bash
power-econ collect -c configs/my_region.yaml --refresh
power-econ features -c configs/my_region.yaml
power-econ train -c configs/my_region.yaml
```

data/real/raw/weather_open_meteo.csv

## 8. 数据质量验收建议

| 项目 | 建议阈值 |
|---|---|
| 总体缺失率 | < 1% |
| 连续负荷缺口 | < 3 小时；更长必须标记 |
| 重复时间戳 | 0 |
| 负负荷 | 0，除非明确为净交换口径 |
| 传感器质量低于 0.5 的时点 | 单独统计和剔除/降权 |
| 事件日志覆盖 | 重点告警期尽量完整 |
| 宏观发布日期 | 可追溯 |
| 口径变更 | 有日期和说明 |

## 9. 将分项负荷加入模型

假设 `load.csv` 有三类分项：

```python
# src/power_econ/features/builder.py

groups["industry"] = [
    "industrial_load_mw",
    "commercial_load_mw",
    "residential_load_mw",
]
```

同时在特征数值化和缺失处理前确认这些列存在。重新执行：

```bash
power-econ collect -c configs/my_region.yaml --refresh
power-econ features -c configs/my_region.yaml
power-econ train -c configs/my_region.yaml
```

模型会从 `feature_spec.json` 自动建立第六个编码分支和门控权重。

## 10. 安全与合规

- 不要把用户、企业或敏感调度信息提交到未批准的外部大模型；
- 可保持 `llm.provider=template` 完全本地运行；
- 若启用外部 LLM，应先做脱敏、访问控制、审计和数据出境评估；
- API 生产部署需增加鉴权、限流、TLS、密钥管理和日志脱敏；
- SQLite 适合原型，生产建议迁移到受控数据库。
